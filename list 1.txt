## **1. Why are we creating this project?**

First, understand the actual insurance business problem.

Imagine an insurance company receives 1,000 life and health insurance applications every day.

Every applicant submits different documents:

- Insurance application form.
- Medical examination report.
- Blood test reports.
- Previous medical history.
- Prescription and medication details.
- Identity and supporting documents.

Currently, underwriters need to examine these documents and compare information manually.

**The real problem is not simply reading documents. The problem is identifying important information that is missing, inconsistent or hidden across different documents.**

| Existing problem          | Business impact                  |
| ------------------------- | -------------------------------- |
| Manual document checking  | More processing time             |
| Missing information       | Incomplete applications          |
| Information mismatch      | Potential underwriting risk      |

**Our solution:** InsureAI reads documents, verifies information, checks underwriting rules, identifies risks and provides an evidence-based recommendation.

It does not independently approve or reject an insurance policy.

## **4. How does the complete application work?**

## **InsureAI processing workflow**

1. **Application submission**

   Applicant submits an insurance form, medical report and lab report.
2. **Document processing**

   Python AI service reads PDFs, scans and extracts information.
3. **Independent verification**

   A second AI reader verifies important extracted information.
4. **Business rule validation**

   Java Spring Boot checks predefined underwriting rules and risk conditions.
5. **Risk classification**

   System proposes a processing route.

   **Clear case**

   Straight-through

   **Uncertain case**

   Human referral

   **Missing information**

   Clarification
6. **Underwriter review**

   Human underwriter reviews evidence and makes the final decision.
7. **Audit and tracking**

   Stores decision history, reasons, timestamps and customer communication.

The central principle is:

# **AI reads → Code validates → AI explains → Human decides**

## **12. Questions your manager might ask**

Prepare for these questions before the meeting.

**Q1. Why do we need Python if we already have Java?**

Java handles the main business application, APIs and underwriting rules. Python provides specialized AI, OCR and machine learning capabilities. Both communicate through REST APIs.

**Q2. Why are we using AI instead of traditional programming?**

Traditional programming works well for predefined rules. However, medical documents contain different formats, unstructured text and scanned information. AI helps understand and extract that information.

**Q3. Can AI approve or reject an insurance policy?**

No. AI provides extracted information, findings and recommendations. The authorized human underwriter makes the final decision.

**Q4. What is MCP and why do we need it?**

MCP allows AI assistants such as Claude or Copilot to access approved application functions through a standardized tool interface. For example, an assistant could retrieve a case summary or explain an existing referral. Access must be authenticated and permission-controlled.

**Q5. How will we protect customer medical information?**

We will implement role-based access, encryption, secure document storage, restricted AI permissions, data masking where appropriate and audit logging. Real customer data will only be used after the insurer's security, privacy and compliance approvals.

**Q6. What is the most important functionality?**

The most important functionality is evidence-based underwriting assessment: extracting information, verifying it, applying rules and showing the underwriter exactly why a case requires attention.
